Technical Memorandum

Digital ROW Management

A Stage II architecture for Philadelphia's ROWDS, centered on trusted asset states and standardized event workflows that can support daily right-of-way operations.

Philadelphia Right-of-Way Data System June 24, 2026
Purpose Current State Proposed Strategy Pilot Proposal Evaluation

Purpose

This memo evaluates Philadelphia's Digital Right-of-Way and Mobility Improvement Project and proposes a Stage II architecture for ROWDS: an evidence-based event workflow built around asset trust and cross-agency coordination.

The proposed operating layer has two parts. The Trusted Asset-State Process supports ongoing asset maintenance, while the Standardized Event Workflow turns permits, closures, utility work, and related operational changes into trackable ROWDS events.

The central shift is from shared data to view toward shared process to operate.

Current State

Stage I's most important achievement was the prototype ROWDS, which gave Philadelphia a more granular way to represent right-of-way assets beyond the street-centerline level. It also established a strong foundation for future service expansion and cross-agency coordination.

The next challenge is operational. ROWDS needs to live inside daily workflows and keep pace with real-world changes. Asset states still require a sustainable trust mechanism, especially because right-of-way conditions can change through permits, utility work, field inspections, sensors, and other operational events.

Stage I also demonstrated that permit data can be converted into ROWDS-compliant Event Policy objects, but that process remained a prototype. Without a live event workflow, coordination can still fall back to manual map checks, email confirmation, and conversations outside the system.

Proposed Strategy

In Stage II, the evidence-based event workflow should respond directly to two gaps: asset trust and workflow standardization.

The Trusted Asset-State Process should avoid updating ROWDS asset states from a single source automatically. Instead, it should define a set of trusted information sources, including Cityworks, permits, utility work, field inspections, and sensors, then standardize those signals into ROWDS-compatible asset-state events.

Each event should carry a consistent information framework: source system, source record ID, timestamp, geometry, affected ROWDS asset ID, change type, proposed state, confidence level, and review status. A state resolution framework can then compare signals across sources and decide whether to keep an existing record, create a temporary state, propose a permanent asset update, or route the case to manual review.

The Standardized Event Workflow should convert street closures, utility work, curb regulation changes, and transit disruptions into trackable ROWDS events. Each event should identify affected assets and route the case to the responsible agencies, keeping review status and decisions in one shared record.

Pilot Proposal

The proposed pilot is utility work permits that require sidewalk closures. This use case involves multiple agencies, temporary changes to right-of-way assets, and high coordination requirements, making it a strong test case for both TASP and SEW.

When a permit enters the existing LaneClosure process, it would become a ROWDS event linked to the affected sidewalk segment, curb segment, and ADA ramp. The shared event record would route review tasks to Streets, the ADA coordinator, and PPA when curb or loading impacts are relevant.

After agency review, the event would feed into the Trusted Asset-State Process as a high-confidence operational event. The system could create a temporary asset state without overwriting the permanent record, then expire that temporary state when the approved time window ends unless new evidence indicates a longer-term change.

Evaluation

The pilot should be evaluated against reductions in off-system coordination, faster agency notification, improved event-to-asset linkage, and stronger evidence trails for future ROWDS updates.
